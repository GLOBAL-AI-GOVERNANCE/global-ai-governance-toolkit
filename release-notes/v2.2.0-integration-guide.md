# v2.2.0 Integration Guide — AI Sovereignty Control Layer

Drop-in upgrade for `GLOBAL-AI-GOVERNANCE/global-ai-governance-toolkit` after the current public `v2.1.0 — Decision-Ready Governance` release line.

**Merge-hygiene rule: this package intentionally contains no root `README.md`.** The flagship README is never replaced. It is edited by hand using the insert blocks below. Every file in this package is additive relative to the current public toolkit structure reviewed on 2026-08-06.

## Integration steps

1. Create the release branch from a clean `main`:

```bash
git checkout main
git pull origin main
git checkout -b v2.2.0-ai-sovereignty-control-layer
```

2. Copy `enterprise/`, `automation/`, `policies/`, `templates/`, `release-notes/`, `.github/`, and `global-ai-governance-toolkit-v2.2.0-sovereignty-add-on-manifest.txt` into the repo root. Use a no-clobber copy and verify nothing existing is touched before manual edits:

```bash
cp -rn <package>/enterprise <package>/automation <package>/policies \
       <package>/templates <package>/release-notes <package>/.github \
       <package>/global-ai-governance-toolkit-v2.2.0-sovereignty-add-on-manifest.txt .

git status   # copied package paths should appear as new files before manual edits
```

If the copy reports that an existing file would be skipped, stop and inspect the conflict before proceeding. Do not overwrite the existing flagship README or existing v2.1.0 release assets.

3. Verify locally. The gate must be green and the demo must block:

```bash
python -B automation/scripts/sovereignty_check.py \
    automation/sample-data/sample-sovereignty-assessment-pass.csv \
    --outdir automation/reports-gate        # expected: exit 0, all PASS

python -B automation/scripts/sovereignty_check.py \
    automation/sample-data/sample-sovereignty-assessment.csv \
    --outdir automation/reports-demo        # expected: exit 1, gates bite

sha256sum -c global-ai-governance-toolkit-v2.2.0-sovereignty-add-on-manifest.txt
```

`automation/reports*` paths are runtime output and should remain untracked. Committed reference reports live in `automation/sample-reports/`. If the repo does not already ignore runtime output, add these lines to `.gitignore`:

```gitignore
automation/reports/
automation/reports-gate/
automation/reports-demo/
```

4. Hand-edit the flagship `README.md`:
   - Current release line: update to `v2.2.0 — AI Sovereignty Control Layer`.
   - Version Lineage: add `v2.2.0: AI Sovereignty Control Layer`.
   - Core Doctrine / Supporting doctrine: append `No sovereignty, no strategic AI.`
   - Repository Map: mention `enterprise/sovereignty`.
   - Add a short "What v2.2.0 Adds" section pointing to `enterprise/sovereignty/` and the run command.

5. Update `CHANGELOG.md` with the v2.2.0 entry below.

6. Add the `sovereignty_law` block to `governance-os.yaml` as a legacy/reference governance configuration block. The current runtime source remains `automation/policy-as-code/governance-rules.yaml`; do not claim this block is runtime-enforced by the v2.1.0 governance pipeline.

7. Commit and ship:

```bash
git add enterprise/sovereignty automation/schemas/sovereignty-assessment.schema.json \
        automation/scripts/sovereignty_check.py automation/sample-data \
        automation/sample-reports policies templates release-notes \
        .github/workflows/sovereignty-check.yml \
        global-ai-governance-toolkit-v2.2.0-sovereignty-add-on-manifest.txt \
        README.md CHANGELOG.md governance-os.yaml .gitignore

git commit -m "Add AI Sovereignty Control Layer to governance toolkit"
git push origin v2.2.0-ai-sovereignty-control-layer
```

Open the PR, confirm the **Sovereignty gate** job is green and the **Enforcement demo** job is non-blocking, merge, then tag `v2.2.0`.

## CI design

- **Sovereignty gate (blocking):** runs the passing baseline CSV; exit 0 keeps the repo green. Point it at the organization's real assessment CSV when ready.
- **Enforcement demo (non-blocking):** runs the intentionally failing sample and exits 1 by design, proving hard gates block non-compliant systems; `continue-on-error: true` keeps the overall workflow status green.
- **Action pinning:** workflow actions are pinned to immutable commit SHAs to align with the current toolkit workflow convention.

## Sovereignty Law block

```yaml
sovereignty_law:
  statement: "No AI system may extract more institutional value than the organization can govern, audit, reverse, or retain."
  rules:
    - "No ZDR or equivalent protection, no sensitive data."
    - "No model liquidity, no strategic dependency."
    - "No audit trail, no production agent."
    - "No granular permissions, no tool access."
    - "No rollback path, no autonomous action."
    - "No owned context layer, no compounding institutional knowledge."
```
